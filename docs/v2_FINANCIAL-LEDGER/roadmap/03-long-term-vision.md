# 장기 방향성 (Long-term Vision)

> 개발 로드맵(`01-development-plan.md`)과 별도로, Fieldstack이 나아갈 수 있는 장기적인 방향을 기록합니다.
> 지금 당장 구현할 것이 아니라 설계 시 염두에 두거나 언젠가 검토할 내용들입니다.

---

## 1. 시장 포지셔닝

### 채울 수 있는 공백

```
SaaS 서비스 (Notion 등)     → 데이터가 내 서버에 없음, 구독료 누적
Odoo / ERPNext              → 무겁고 설치 난이도 높음, 기업 타깃
단일 기능 툴 (Firefly 등)   → 확장이 안 됨, 연동이 없음

Fieldstack →
  내 서버에서 돌아가고, 가볍고 현대적이며,
  필요한 모듈만 골라 쓸 수 있는 자기 호스팅 업무 시스템
```

Odoo와 가장 유사한 포지션이지만 직접 경쟁이 아닌 **"Odoo를 쓰기엔 너무 작고, 단일 툴로는 부족한"** 개인 / 프리랜서 / 소규모 팀을 타깃으로 합니다.

### 최근 유리한 환경 변화
- 데이터 주권 인식 증가 (내 데이터가 어디 있는지 신경 쓰는 사람 증가)
- SaaS 피로감 (구독 서비스 과다)
- Docker 대중화로 자기 호스팅 진입장벽 하락
- AI 코딩 툴로 소규모 팀도 모듈 직접 제작 가능

## 2. SaaS 확장 가능성

### 방향

자기 호스팅(오픈소스)과 SaaS(유료 구독)를 동시에 제공하는 모델.
GitLab, Odoo, Plane 등이 채택한 방식.

```
자기 호스팅 (Self-hosted)
  └─ 오픈소스, 무료, 기술 있는 사용자
  └─ 커뮤니티와 신뢰 형성

SaaS (Managed Cloud)
  └─ 설치 없이 바로 사용
  └─ 구독 요금으로 수익화
  └─ 일반 사용자 / 비기술 사용자 타깃
```

### 비즈니스 모델 옵션

| 모델 | 구조 | 비고 |
|------|------|------|
| Open Core | 자기 호스팅 무료 + SaaS 유료 | 가장 현실적 |
| Freemium | SaaS 기본 무료 + 프리미엄 유료 | 사용자 모으기 유리 |
| 모듈 유료화 | 코어 무료 + 일부 모듈 유료 | 마켓플레이스와 연계 |
| Enterprise tier | 기업용 지원/기능 별도 유료 | 장기 목표 |

### 설계 시 염두에 둘 것 (지금 당장 X)

- DB 스키마 설계 시 `tenant_id` 컬럼 추가 여지를 남겨둘 것
- 멀티 테넌시 전환 시 모듈 코드 자체는 거의 그대로 사용 가능 (모듈 독립 구조 덕분)
- 결제/구독 관리 인프라는 별도 필요

## 3. 결제 시스템

### Subscription 모듈과의 구별

`Subscription 모듈`은 결제 처리 시스템이 **아닙니다.**
사용자가 외부에서 구독 중인 서비스들을 정리·추적하는 모듈입니다:
- 구독 중인 서비스 목록 및 금액
- 결제일 알림
- 월간/연간 지출 계산
- Ledger 모듈 연동 (지출 자동 기록)

### 실제 결제 연동이 붙을 위치

`Project/Outsource 모듈` (`_modules_for-future/02-project-outsource.md`) 이 가장 자연스러운 위치입니다:
- 견적서 발행 → 인보이스 생성 → **결제 링크 첨부**
- 외부 결제 서비스(토스페이먼츠, PayPal 등)를 링크 형태로 연결
- 결제 완료 웹훅 수신 → 정산 상태 자동 업데이트 → Ledger 수입 자동 기록

> 직접 결제를 처리하는 게 아니라 외부 결제 서비스로 연결하고 상태만 받아오는 방식.
> PG사 직접 연동은 법적 요건(전자금융업 등록 등)이 있어 현실적으로 외부 위임이 맞습니다.

## 4. 확장 가능한 모듈 방향

모듈 시스템이 갖춰지면 이론적으로 제한 없이 확장 가능합니다.

### 개인 / 프리랜서
| 모듈 | 설명 |
|------|------|
| 청구서 / 인보이스 | 공유 링크 발행, PDF 내보내기, 결제 링크 연결 |
| 클라이언트 관리 | 거래처별 히스토리, 연락처, 프로젝트 연결 |
| 시간 추적 | 프로젝트별 작업 시간 기록, 청구서 자동 계산 |
| 계약서 관리 | 계약 기간, 갱신일 알림, 전자계약 연동 |

### 소규모 팀 / 회사
| 모듈 | 설명 |
|------|------|
| 출퇴근 관리 | 출퇴근 기록, 근무 시간 집계 |
| 사원 관리 | 사원 정보, 직책, 계약 정보 |
| 경비 처리 | 경비 신청, 승인, Ledger 연동 |
| 공지 / 사내 게시판 | 내부 공지 관리 |

### 정보 / 콘텐츠
| 모듈 | 설명 |
|------|------|
| 노트 / 저널 | 날짜별 기록, 태그, 검색 |
| 자산 관리 | 보유 자산 목록, 감가상각, Ledger 연동 |
| 폼 빌더 | 외부 공개 링크, 응답 수집 |
| 상태 페이지 | 외부에 공개하는 서비스 상태 |

## 5. 공유 링크 코어 시스템

어떤 모듈이든 외부 공개 링크를 발행할 수 있는 공통 인프라.
설계 상세는 `technical/08-shared-link.md` 참고.

```
청구서 모듈  ─┐
폼 빌더      ─┼─→ 공유 링크 코어 → 외부 접속자
프로젝트     ─┘
```

모듈은 "이 데이터를 외부에 어떻게 보여줄지"만 정의하면 됩니다.
링크 발행 / 만료 / 접근 제어 / 로깅은 코어가 처리합니다.

## 6. 마켓플레이스 수익 모델

### 유료 모듈 / 테마 수수료

개발자가 마켓플레이스에 유료 모듈 또는 테마를 등록할 수 있으며,
결제된 금액 중 **5%를 Fieldstack 운영 수수료**로 수취합니다.

```
사용자가 유료 모듈 구매 (예: 10,000원)
  └─ 개발자 수취: 9,500원 (95%)
  └─ Fieldstack 수수료: 500원 (5%)
```

### 수수료 책정 근거

- Apple / Google 앱스토어: 30%
- Steam (게임): 30%
- Gumroad: 10%
- **Fieldstack: 5%** — 개발자 친화적, 생태계 형성 우선

개발 및 서버 운영 유지 명목의 최소 비용만 확보하는 것이 목적이며,
수익보다는 **모듈/테마 생태계를 키우는 것**을 우선합니다.

### 무료 모듈 / 테마

수수료 없이 자유롭게 등록 가능합니다.
오픈소스 생태계 활성화를 위해 무료 등록에는 제한을 두지 않습니다.

### 구현 시 필요한 것

- 마켓플레이스 자체 결제 처리 (Stripe 또는 Paddle 연동)
- 개발자 정산 시스템 (월별 또는 기준액 도달 시 자동 송금)
- 라이선스 키 발급 및 검증 (구매 확인 / 무단 배포 방지)
- 환불 정책 정의

> 구현 시점: Phase 3 마켓플레이스 구축 이후, 생태계가 어느 정도 형성된 시점에 도입.

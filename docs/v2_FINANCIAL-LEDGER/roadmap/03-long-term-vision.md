# 장기 방향성 (Long-term Vision)

> 개발 로드맵(`01-development-plan.md`)과 별도로, Fieldstack이 나아갈 수 있는 장기적인 방향을 기록합니다.
> 지금 당장 구현할 것이 아니라 설계 시 염두에 두거나 언젠가 검토할 내용들입니다.

---

## 1. 시장 포지셔닝

### 채울 수 있는 공백

```
SaaS 서비스 (Notion 등)     → 데이터가 내 서버에 없음, 구독료 누적
Odoo / ERPNext              → 무겁고 설치 난이도 높음, 기업 타깃
단일 기능 툴 (Firefly 등)   → 확장이 안 됨, 연동이 없음

Fieldstack →
  내 서버에서 돌아가고, 가볍고 현대적이며,
  필요한 모듈만 골라 쓸 수 있는 자기 호스팅 업무 시스템
```

Odoo와 가장 유사한 포지션이지만 직접 경쟁이 아닌 **"Odoo를 쓰기엔 너무 작고, 단일 툴로는 부족한"** 개인 / 프리랜서 / 소규모 팀을 타깃으로 합니다.

### 최근 유리한 환경 변화
- 데이터 주권 인식 증가 (내 데이터가 어디 있는지 신경 쓰는 사람 증가)
- SaaS 피로감 (구독 서비스 과다)
- Docker 대중화로 자기 호스팅 진입장벽 하락
- AI 코딩 툴로 소규모 팀도 모듈 직접 제작 가능

## 2. SaaS 확장 가능성

### 방향

자기 호스팅(오픈소스)과 SaaS(유료 구독)를 동시에 제공하는 모델.
GitLab, Odoo, Plane 등이 채택한 방식.

```
자기 호스팅 (Self-hosted)
  └─ 오픈소스, 무료, 기술 있는 사용자
  └─ 커뮤니티와 신뢰 형성

SaaS (Managed Cloud)
  └─ 설치 없이 바로 사용
  └─ 구독 요금으로 수익화
  └─ 일반 사용자 / 비기술 사용자 타깃
```

### 비즈니스 모델 옵션

| 모델 | 구조 | 비고 |
|------|------|------|
| Open Core | 자기 호스팅 무료 + SaaS 유료 | 가장 현실적 |
| Freemium | SaaS 기본 무료 + 프리미엄 유료 | 사용자 모으기 유리 |
| 모듈 유료화 | 코어 무료 + 일부 모듈 유료 | 마켓플레이스와 연계 |
| Enterprise tier | 기업용 지원/기능 별도 유료 | 장기 목표 |

### 설계 시 염두에 둘 것 (지금 당장 X)

- DB 스키마 설계 시 `tenant_id` 컬럼 추가 여지를 남겨둘 것
- 멀티 테넌시 전환 시 모듈 코드 자체는 거의 그대로 사용 가능 (모듈 독립 구조 덕분)
- 결제/구독 관리 인프라는 별도 필요

## 3. 결제 시스템

### Subscription 모듈과의 구별

`Subscription 모듈`은 결제 처리 시스템이 **아닙니다.**
사용자가 외부에서 구독 중인 서비스들을 정리·추적하는 모듈입니다:
- 구독 중인 서비스 목록 및 금액
- 결제일 알림
- 월간/연간 지출 계산
- Ledger 모듈 연동 (지출 자동 기록)

### 실제 결제 연동이 붙을 위치

`Project/Outsource 모듈` (`../modules/future/02-project-outsource.md`) 이 가장 자연스러운 위치입니다:
- 견적서 발행 → 인보이스 생성 → **결제 링크 첨부**
- 외부 결제 서비스(토스페이먼츠, PayPal 등)를 링크 형태로 연결
- 결제 완료 웹훅 수신 → 정산 상태 자동 업데이트 → Ledger 수입 자동 기록

> 직접 결제를 처리하는 게 아니라 외부 결제 서비스로 연결하고 상태만 받아오는 방식.
> PG사 직접 연동은 법적 요건(전자금융업 등록 등)이 있어 현실적으로 외부 위임이 맞습니다.

모듈 시스템이 갖춰지면 이론적으로 제한 없이 확장 가능합니다.

| 모듈 | 설명 |
|------|------|

| 계약서 관리 | 계약 기간, 갱신일 알림, 전자계약 연동 |

### 소규모 팀 / 회사
| 모듈 | 설명 |

## 5. 에디터 라이브러리 (`@docuverse/editor`)

### 방향

에디터는 원래 DocuVerse 프로젝트에서 기획된 것으로, **DocuVerse 소속 라이브러리로 독립 개발**합니다.
Fieldstack은 이를 외부 패키지로 가져다 사용하는 방식입니다.

**개발의 중심은 순수 에디터 코어**이며, 협업·내보내기 등 부가 기능은 에디터의 **플러그인**으로 분리합니다.
Fieldstack 모듈은 Note, Wiki처럼 용도 단위로만 나뉩니다.

```
[DocuVerse 프로젝트] @docuverse/editor
    ├── core/              ← 순수 에디터 코어
    └── plugins/
          ├── collab/      ← 실시간 협업 (yjs) — 필요 시 로드
          ├── export/      ← PDF·HTML 내보내기 — 필요 시 로드
          └── code/        ← 코드 구문 강조 언어팩 — 필요 시 로드

[Fieldstack 프로젝트] @docuverse/editor 를 외부 의존성으로 사용
modules/
  note/            ← @docuverse/editor 사용, 노트 기능
  wiki/            ← @docuverse/editor 사용, 위키 구조
```

### 에디터를 외부 패키지로 두는 이유

- 에디터의 원 소속이 DocuVerse이므로 프로젝트 귀속을 명확히 유지
- DocuVerse를 본격 개발할 때 에디터를 그대로 이어받아 사용 가능
- Fieldstack 릴리즈 사이클과 에디터 개발 사이클이 분리되어 서로 발목을 잡지 않음
- 에디터를 사용하지 않는 Fieldstack 모듈/페이지에 번들 부담 없음

### 에디터 코어 범위

에디터 코어는 **순수하게 글을 쓰는 기능**에만 집중합니다.

| 포함 (코어) | 플러그인으로 분리 |
|------------|----------------|
| TipTap + ProseMirror 기반 블록 에디터 | 실시간 협업 (yjs) |
| WYSIWYG + Markdown 듀얼 모드 | PDF / HTML 내보내기 |
| 나무위키 스타일 표 (셀 병합, 중첩) | 코드 구문 강조 언어팩 |
| 문서 구조 (목차, 접기/펼치기, 앵커) | 외부 스토리지 연동 |
| 기본 서식 (굵게, 기울임, 코드 등) | AI 어시스턴트 연동 |
| 이미지 / 파일 첨부 (로컬) | |

> 코어만으로도 충분히 쓸 수 있는 에디터를 목표로 합니다.
> 플러그인은 필요할 때만 로드하는 방식이라 번들 부담이 없습니다.

### 번들 크기 목표

```
에디터 코어 (gzip 기준)    ~50~70KB
  — 협업, PDF, 언어팩 전부 제외한 순수 에디터
  — 일반적인 웹앱 컴포넌트 수준
```

### 활용 범위

DocuVerse 소속이지만 범용 라이브러리로 설계합니다:
- Fieldstack Note·Wiki 모듈에서 사용
- DocuVerse 앱 본체에서 사용
- 필요 시 npm 공개 패키지로 배포, 외부 프로젝트에서도 사용 가능

> 개발 시점: DocuVerse 에디터 개발이 준비되는 시점에 시작.
> Fieldstack Note·Wiki 모듈은 에디터가 완성된 이후 개발.

## 7. 공유 링크 코어 시스템

어떤 모듈이든 외부 공개 링크를 발행할 수 있는 공통 인프라.
설계 상세는 `technical/07-shared-link.md` 참고.

```
청구서 모듈  ─┐
폼 빌더      ─┼─→ 공유 링크 코어 → 외부 접속자
프로젝트     ─┘
```

모듈은 "이 데이터를 외부에 어떻게 보여줄지"만 정의하면 됩니다.
링크 발행 / 만료 / 접근 제어 / 로깅은 코어가 처리합니다.

## 8. 마켓플레이스 수익 모델

### 유료 모듈 / 테마 수수료

> **결정된 방식**: Fieldstack 수수료 5% + 외부 결제 수수료(Stripe 등 ~3%) 별도 공시.
> 실질 부담률 ~8%는 타 플랫폼(10% 이상) 대비 여전히 개발자 친화적입니다.

개발자가 마켓플레이스에 유료 모듈 또는 테마를 등록할 수 있으며,
결제된 금액 중 **5%를 Fieldstack 운영 수수료**로 수취합니다.
외부 결제 처리 수수료(Stripe 등 약 2.9%+α)는 별도로 발생하며,
정산 화면에 명확히 분리 표시합니다.

```
사용자가 유료 모듈 구매 (예: 10,000원)
  └─ 결제 처리 수수료 (Stripe ~3%): 약 300원
  └─ Fieldstack 운영 수수료 (5%): 500원
  └─ 개발자 실수취: 약 9,200원 (92%)

실질 총 부담률: ~8%  (타 플랫폼 10~30% 대비 낮음)
```

### 수수료 책정 근거

| 플랫폼 | 수수료 | 비고 |
|--------|--------|------|
| Apple / Google 앱스토어 | 30% | 결제 수수료 포함 |
| Steam | 30% | |
| Gumroad | 10% | 결제 수수료 포함 |
| **Fieldstack** | **5% + 결제 수수료 (~3%)** | 합산 ~8%, 투명 공시 |

개발 및 서버 운영 유지 명목의 최소 비용만 확보하는 것이 목적이며,
수익보다는 **모듈/테마 생태계를 키우는 것**을 우선합니다.

### 무료 모듈 / 테마

수수료 없이 자유롭게 등록 가능합니다.
오픈소스 생태계 활성화를 위해 무료 등록에는 제한을 두지 않습니다.

### 구현 시 필요한 것

- 마켓플레이스 자체 결제 처리 (Stripe 또는 Paddle 연동)
- 개발자 정산 시스템 (월별 또는 기준액 도달 시 자동 송금)
- 라이선스 키 발급 및 검증 (구매 확인 / 무단 배포 방지)
- 환불 정책 정의

> 구현 시점: Phase 3 마켓플레이스 구축 이후, 생태계가 어느 정도 형성된 시점에 도입.
